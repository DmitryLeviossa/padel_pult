<objective>
Create four new SCSS partials and make targeted additions to two existing SCSS files so that cards, form inputs, and table headers render with the project's dark design tokens.

Purpose: Bootstrap 5.3 compiles CSS custom properties as LOCAL declarations on component elements (`.card { --bs-card-bg: X }`). These local declarations win over inherited values from `[data-bs-theme="dark"]` on `<html>`. The `_theme.scss` overrides for `--bs-card-bg` and `--bs-input-bg` are therefore cascade-ineffective. This plan adds direct `background-color` property overrides (later source order, equal specificity) to close the gap.

Output: 4 new SCSS partial files + 2 modified SCSS files + 1 updated manifest. No template or Ruby changes.
</objective>

**_variables.scss:** Add one line immediately after the `$dark: #21262d;` line (currently line 11):

```scss
$input-bg:         var(--color-bg-surface); // COMP-03: dark input surface; propagates to form-control, form-select, textarea
```

The line must appear BEFORE Bootstrap's variable import in application.bootstrap.scss (already true — _variables.scss is imported before Bootstrap). This causes Bootstrap to compile `.form-control { background-color: var(--color-bg-surface); }` directly, affecting form-control, form-select, textarea, and input-group variants in one change. Do NOT add this to _theme.scss — SCSS variables in _theme.scss (imported after Bootstrap) cannot retroactively change already-compiled Bootstrap output.

**_theme.scss:** Add three lines inside the `[data-bs-theme="dark"]` block, immediately before the closing `}` brace (after the `--bs-input-placeholder-color` line, currently line 43):

```scss
  --bs-tertiary-bg:              var(--color-bg-navbar);    // COMP-03: file-selector-button bg (#161b22 — darker than input, clear visual separation)
  --bs-box-shadow-sm:            none;                       // COMP-01: suppress invisible light-theme shadows on dark backgrounds
  --bs-box-shadow:               none;                       // COMP-01: suppress .shadow utility on dark backgrounds
```

Alignment: pad with spaces so all values align at column 33, matching the existing block style (look at how `--bs-input-placeholder-color:` is spaced in the existing file).

The `--bs-box-shadow-sm: none` approach is correct because Bootstrap's `.shadow-sm` utility is `box-shadow: var(--bs-box-shadow-sm) !important`. Setting the CSS variable to `none` makes the `!important` value evaluate to `none` — no specificity conflict needed.
  </action>
