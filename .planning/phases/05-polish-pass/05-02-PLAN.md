// Card dark surface + border overrides — bypasses Bootstrap's cascade-ineffective --bs-card-bg.

.card {

// POLL-02: Hover lift utility. Add `.card-hoverable` to any .card that should react to hover
// (typically cards with a stretched-link child — e.g. leagues/index, dashboard recent leagues).
// Uses transform (not top/left) so there is zero layout shift on neighboring elements.
.card-hoverable:hover {

  border-color: var(--color-accent-hover);

Critical constraints (from RESEARCH.md Pitfall 1):
- The `transition: $transition-base;` line MUST be inside the base `.card { }` block — NOT inside `.card-hoverable:hover`. If transition is only on :hover, the leave animation (mouseout) is instant and snaps. Putting it on the base rule applies it to BOTH enter and leave.
- The hover rule MUST use `transform: translateY(-1px)` — NOT `top: -1px` or `margin-top: -1px` — so the element moves in the compositor without affecting layout.
- Do NOT change `padding`, `margin`, `border-width`, or `width`/`height` on hover. Only `transform` and `border-color` may change.
- Use `var(--color-accent-hover)` (which resolves to #4d94f8) for the brightened border — exactly per UI-SPEC. Do NOT hard-code the hex.
- Preserve the existing `.card-header, .card-footer` rule unchanged.
- Do NOT use `a > .card` or `.card-link > .card` selectors — per user decision lock, we use `.card-hoverable` instead.
