**Create `app/views/layouts/_flash.html.slim`:**

```slim
- type_map = { "notice" => "alert-success", "alert" => "alert-danger", "warning" => "alert-warning", "info" => "alert-info" }
- flash.each do |type, message|
  .alert.alert-dismissible.fade.show role="alert" class=type_map.fetch(type, "alert-secondary") data-controller="flash" data-flash-delay-value="5000" data-turbo-temporary="true"
    = message
    button.btn-close type="button" data-bs-dismiss="alert" data-action="flash#close" aria-label="Close"
```

CRITICAL: Use `= message` (NOT `== message`). Slim's `=` auto-escapes HTML — this prevents XSS. The `==` raw output operator must never be used for flash message content.

`data-turbo-temporary="true"` prevents Turbo Drive from caching the flash element in its DOM snapshot. Without this, flash messages reappear when the user presses browser back.

Both `data-bs-dismiss="alert"` and `data-action="flash#close"` are present:
- `data-bs-dismiss="alert"` → Bootstrap handles the CSS fade-out transition on click
- `data-action="flash#close"` → Stimulus clears the auto-dismiss timer and triggers removal

Flash type mapping:
- `"notice"` → `alert-success` (green tint — `--color-success: #3fb950`)
- `"alert"` → `alert-danger` (red tint — `--color-danger: #f85149`)
- `"warning"` → `alert-warning` (yellow tint — `--color-warning: #d29922`)
- `"info"` → `alert-info`
- Any other key → `alert-secondary`

Bootstrap dark alert variants are automatic via `data-bs-theme="dark"` on `<html>` — no custom dark CSS needed.

**Create `app/javascript/controllers/flash_controller.js`:**

```javascript
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static values = { delay: { type: Number, default: 5000 } }

  connect() {
    this.timer = setTimeout(() => this.close(), this.delayValue)
  }

  disconnect() {
    clearTimeout(this.timer)
  }

  close() {
    this.element.classList.remove("show")
    this.element.addEventListener("transitionend", () => this.element.remove(), { once: true })
  }
}
```

`disconnect()` clears the timer — prevents acting on a removed element when Turbo navigates away before the 5-second auto-dismiss fires. `{ once: true }` on the transitionend listener prevents memory leaks.

`eagerLoadControllersFrom` auto-registers this as identifier `"flash"` — no manual registration needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server → Browser (flash rendering) | `_flash.html.slim` renders Rails flash hash values into HTML — user-influenced content (e.g. from form submissions) crosses this boundary |
| Browser → JS timer | Stimulus flash controller sets a setTimeout that fires in the browser context — no network crossing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering / XSS | `_flash.html.slim` — `= message` output | mitigate | Use Slim `=` operator (HTML-escaping) — NEVER `== message` (raw). Flash values originate from Rails server-side `flash[]` assignments. Devise and Rails controllers set flash from server-controlled strings, not from raw user input, but defense-in-depth requires escaping regardless. Verified in acceptance criteria. |
| T-02-08 | Tampering | Turbo snapshot caching flash element | mitigate | `data-turbo-temporary="true"` on each alert div prevents Turbo from including flash elements in DOM snapshots. Without this, flash reappears on back-navigation. |
| T-02-09 | Denial of Service | Stimulus timer firing after element removed | mitigate | `disconnect()` calls `clearTimeout(this.timer)` — prevents timer callback running on a removed/disconnected element. `{ once: true }` on `transitionend` prevents listener accumulation. |
| T-02-10 | Information Disclosure | Flash message content visible to all users on page | accept | Flash messages are session-scoped (Rails flash hash is per-user per-request). No cross-user data disclosure possible. |
| T-02-11 | Spoofing | `application.html.slim` rendering navbar without auth check | accept | The navbar partial itself contains `user_signed_in?` guards. The layout always renders the navbar — signed-out state shows only Войти/Регистрация links. Actual route authorization is enforced in controllers via `before_action :authenticate_user!`. |
| T-02-12 | Tampering | `application.bootstrap.scss` — new @import paths | accept | Import paths are static string literals authored by developer, committed to git. No dynamic path construction. No registry fetch. Dart Sass resolves paths at build time from the local filesystem only. |
</threat_model>
