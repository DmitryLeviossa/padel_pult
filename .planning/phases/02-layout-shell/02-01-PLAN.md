**navbar_controller.js:**

Create `app/javascript/controllers/navbar_controller.js` with this exact content:

```javascript
import { Controller } from "@hotwired/stimulus"
import { Collapse } from "bootstrap"

export default class extends Controller {
  static targets = ["menu"]

  toggle() {
    const collapse = Collapse.getOrCreateInstance(this.menuTarget)
    collapse.toggle()
  }
}
```

The named import `{ Collapse }` works with the importmap-pinned bootstrap bundle. The controller delegates to Bootstrap's Collapse API — it does NOT reimplement toggle logic with `classList.toggle("show")`. `getOrCreateInstance` ensures idempotency.

`eagerLoadControllersFrom("controllers", application)` in `app/javascript/controllers/index.js` auto-registers this as identifier `"navbar"` — no manual registration needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server → Browser (view rendering) | `_navbar.html.slim` renders user data (`current_user.full_name`) server-side into HTML sent to browser |
| Browser → Server (logout action) | `button_to destroy_user_session_path, method: :delete` crosses trust boundary — CSRF token required |
| Client JS → Bootstrap API | `navbar_controller.js` calls Bootstrap's Collapse API — no trust boundary, same origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | `_navbar.html.slim` — `user_signed_in?` check | accept | Devise `user_signed_in?` is the authoritative server-side auth check; no spoofing possible via client |
| T-02-02 | Tampering | `button_to "Выйти", destroy_user_session_path, method: :delete` — logout CSRF | mitigate | `button_to` with `method: :delete` generates a Rails-managed `<form>` with `authenticity_token` hidden field — CSRF protected by default. Do NOT use `link_to` with method: :delete (no form = no CSRF token) |
| T-02-03 | Tampering | `_navbar.html.slim` — XSS via user display data | accept | Slim's `=` operator HTML-escapes all output. `current_user.full_name` is server-side data already sanitized by ActiveRecord/Devise. No unescaped `==` operator used. |
| T-02-04 | Information Disclosure | User initials in navbar | accept | Initials (2 chars) reveal minimal PII — consistent with existing app behavior showing user email. Not a new exposure. |
| T-02-05 | Elevation of Privilege | `user_signed_in?` gating nav links | accept | Nav link visibility is presentation-only; actual authorization is enforced in controllers via `before_action :authenticate_user!`. Hiding links is UX, not security. |
| T-02-06 | Denial of Service | Stimulus controller double-fire (Pitfall 1) | mitigate | Do NOT add `data-bs-toggle="collapse"` to the hamburger button when using Stimulus. Only `data-action="navbar#toggle"` is present. Verified in acceptance criteria. |
</threat_model>
